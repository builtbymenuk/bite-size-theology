Deployment Runbook

Putting Bite Size Theology live on Hostinger

Stack: Next.js 16 · Strapi 5.50.2 · Node 22 · MySQL — on a Hostinger plan with Node.js hosting + SSH (Business/Premium tier).

💡 The big picture — This is a custom app, so "going live" is a one-time developer task (~1–2 hrs). You run two Node programs on the one plan: Strapi (the admin + API, on a cms. subdomain, backed by MySQL) and the Next.js site (the public site, on the main domain). After it's live, the client edits everything from the Strapi admin — no code.
⚠ Read this first — Strapi is memory-hungry and runs continuously. Shared hosting can run it, but if it's slow or keeps dying (out-of-memory, timeouts), the standard fix is a cheap Hostinger VPS just for Strapi, keeping the Next site on this plan. Same steps; STRAPI_URL just points at the VPS. Also confirm your plan actually has SSH access — you need it to build.

0What you need before starting

  • Hostinger plan with Node.js + SSH (hPanel → Advanced shows "Node.js" and "SSH Access")
  • The domain (pointed at this Hostinger account)
  • Access to the GitHub repo builtbymenuk/bite-size-theology
  • Live PayPal + Stripe keys (or use them later — checkout just stays hidden until set)
  • An SSH client (Windows Terminal / PowerShell has ssh built in)

1Prepare the code (do locally, commit, push)

a. Add the MySQL driver to Strapi

cd cms
npm install mysql2

Your cms/config/database.ts already supports MySQL — it just needs this driver.

b. Make Next.js output a self-contained server

In next.config.ts, add one line inside the config object:

output: "standalone",

This makes npm run build produce .next/standalone/server.js — a ready-to-run server for Hostinger's Passenger.

c. Add a Strapi start file for Passenger

Create cms/server.js:

// Passenger entry — starts Strapi in production (run `npm run build` first)
const { createStrapi } = require("@strapi/strapi");
createStrapi().start();

d. Generate production secrets

Run this once and save the output — you'll paste these into the Strapi app's env vars (step 6). Never reuse the dev secrets.

node -e "const c=require('crypto'),k=()=>c.randomBytes(16).toString('base64');console.log('APP_KEYS='+[k(),k(),k(),k()].join(','));['API_TOKEN_SALT','ADMIN_JWT_SECRET','TRANSFER_TOKEN_SALT','JWT_SECRET','ENCRYPTION_KEY'].forEach(n=>console.log(n+'='+k()))"

Commit a & b & c and push to GitHub.

2Create the MySQL database (hPanel)

hPanel → Databases → MySQL Databases → create a database + user. Write down:

  • Database name, username, password
  • Host is usually localhost, port 3306

3Create the subdomain + enable SSH (hPanel)

  • Domains → Subdomains → create cms → note the folder it creates (e.g. domains/bitesizetheology.com/cms).
  • Advanced → SSH Access → make sure it's enabled; copy the SSH host/port/username.

4Get the code onto the server

SSH in, then clone the repo into two folders — one for the site, one for Strapi:

ssh u123456789@your-server -p 65002        # use YOUR ssh details

git clone https://github.com/builtbymenuk/bite-size-theology.git site
cp -r site/cms cms          # Strapi lives in the repo's cms/ subfolder

cd ~/site && npm ci        # install site deps
cd ~/cms  && npm ci        # install Strapi deps
💡 Keep the two apps in separate folders (~/site and ~/cms) — Passenger maps one folder per app.

5Build both apps

# Strapi — builds the admin panel
cd ~/cms && NODE_ENV=production npm run build

# Next — builds the site (standalone output)
cd ~/site && npm run build
# standalone needs static + public copied in beside server.js:
cp -r .next/static .next/standalone/.next/static
cp -r public       .next/standalone/public
⚠ The #1 thing that goes wrong: out-of-memory during build. Shared hosting has limited RAM. If a build is "Killed": retry with NODE_OPTIONS=--max-old-space-size=1536 npm run build, or build on your own computer (same Node 22) and upload the built folders (cms/dist + cms/build, and the whole site/.next/standalone) via SFTP instead.

⚠ Deploy Strapi first. The Next build bakes in STRAPI_URL and the public PayPal id (see step 7), so Strapi's URL must exist before you build/deploy Next.

⚠ Build-time vs runtime. STRAPI_URL and NEXT_PUBLIC_PAYPAL_CLIENT_ID are baked into the site when you build it — they must be set in the shell (or a .env.production in ~/site) before npm run build, not only in hPanel. The rest (STRAPI_API_TOKEN, secrets, Stripe/PayPal secret) are read at runtime, so hPanel is fine for those. If you change a NEXT_PUBLIC_ value, you must rebuild.

8Start, secure, and wire up

  1. SSL — hPanel → SSL → enable free Let's Encrypt for both the domain and the cms. subdomain.
  2. Start Strapi (Restart in its Node app). Visit https://cms.bitesizetheology.com/admin → create the admin account. It auto-seeds all content + the 15 podcast episode slots.
  3. API token — in Strapi: Settings → API Tokens → Create (Full access) → paste the value into the Next app's STRAPI_API_TOKEN → restart the Next app.
  4. Instant updates (optional) — Strapi: Settings → Webhooks → new webhook to https://bitesizetheology.com/api/revalidate?secret=<REVALIDATE_SECRET>, trigger on entry create/update/delete. Without this, edits appear within ~5 min.
  5. Start Next and open the main domain.

9Verify it's really working

  • Main domain loads the homepage with real content
  • cms. subdomain admin loads and lets you log in
  • Edit a headline in Strapi → reload the site → it changed
  • Upload a product/episode image in Strapi → it shows on the site (not a placeholder)
  • Add to cart → checkout → a test PayPal/Stripe payment → order appears in Strapi → Store — Orders

10If something breaks

SymptomLikely cause / fix
Build says "Killed"Out of memory. Use NODE_OPTIONS=--max-old-space-size=1536, or build locally and upload.
App won't start / 502Wrong startup file or root folder; or you forgot to build. Check the app's log in hPanel. Strapi needs dist/+build/; Next needs static/public copied into standalone.
Strapi: "Missing …_SECRET"One of the 6 secrets isn't set in the Strapi app env.
Site loads but images are brokenSTRAPI_URL wasn't set at build time, or SSL isn't on the cms. subdomain (mixed content). Rebuild Next with STRAPI_URL set.
Checkout button missingPayment keys not set — that's the built-in safe behavior. Set them and restart (PayPal public id needs a rebuild).
DB connection errorWrong DATABASE_* values, or the MySQL user isn't attached to the database.
Strapi keeps dyingRAM limits on shared hosting. Move Strapi to a small VPS (see the warning at the top).

11Pushing updates later

ssh in → cd ~/site && git pull && npm ci && npm run build
cp -r .next/static .next/standalone/.next/static && cp -r public .next/standalone/public
# then Restart the Next app in hPanel

# if Strapi code/schema changed:
cd ~/cms && git -C ../site pull && cp -r ../site/cms/* . && npm ci && npm run build
# then Restart the Strapi app

Content changes (text, images, products, orders) never need a redeploy — those are all in the CMS.
